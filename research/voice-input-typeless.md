# 用說的跟 AI 工作：Typeless 真的強，自己蓋的差在清稿

讀 **7 分鐘**｜最後驗證 **2026.10.12**｜Mac（M4 Max）本機實測

> **你會知道：**在 Mac 上用說的打繁體中文，Typeless 和自己用 Whisper 在本機架的語音輸入差在哪；同一段話三種輸出長什麼樣；轉文字、清稿各花幾秒；反過來讓 AI 開口回話，台灣腔的語音怎麼選；以及到現在還沒解的兩題。

## 先講結論

語音輸入分兩段：**先把聲音轉成文字，再把口語「清稿」成好讀的文字**。轉文字這段，免費的 Whisper 在 Mac 本機就跑得又快又準；真正拉開差距的是清稿。

**2026-10 實測**：我自己架的那套，現在轉文字只要 0.6 秒；放開按鍵到貼上，短句 2.8 秒、長段 11.6 秒，Typeless 是 1.4／4.1 秒，它仍快 2–2.8 倍。差距全在清稿。

影片拍攝時（2026-08）長錄音是 30.6 秒對 4.1 秒，差 7.5 倍；這兩個月我這邊快了約 2.6 倍，Typeless 幾乎沒變。

### 直接用 Typeless

- 想今天就開始用說的打字，不想動手架
- 在意「放開就出字」的速度
- 喜歡它替你分段、列點、補成完整句子

### 自己架一個

- 錄音不想離開自己的電腦（轉文字在本機跑）
- 要它只去贅詞、不替你加字
- 常講專有名詞，想自己養一本辭典
- 願意花時間調，接受清稿這段還比較慢

想找 Typeless 的免費替代：轉文字可以完全免費在本機跑；清稿要嘛用你已經有的 AI 訂閱，要嘛用本機小模型——後者到現在品質還不夠用，數字在下面。

## 為什麼要用說的

我天天跟 AI 一起開發，兩個月下來發現，累的不是想，是**打字和讀字**。每一輪對話都要打一長段、再讀一長段，決策的力氣被這兩件事吃掉。換成用說的，同一段想法講出來比打出來快很多，跟 AI 溝通的效率差非常多。

網路上被最多人推薦的語音輸入是 Typeless。它的做法可以理解成兩步：

1. **語音模型**把你說的話轉成文字。
2. **大語言模型**把這串口語整理成乾淨的文字：去掉贅詞、改口，補標點、分段。

這是我們從使用行為整理出來的理解，不是 Typeless 官方說明。

它方便的地方是可以一直開著講，像會議紀錄一樣替你統整，出來的東西易讀易懂。

## 同一段話，三種輸出

拿一段 148 秒的口述（在講 HDR 影片的取捨）當題目，看三種輸出：

原始逐字稿（沒清稿）· 455 字

Typeless · 559 字（＋23%）

自己架的（Whisper large-v3 轉文字＋清稿）· 425 字（−7%）

> 原始逐字稿・開頭：我在研究一個HDR的影片然後最近把Xlog3的素材全部拿來做剪輯那這當中我目前感受度就是HDR的影片好像是一種取捨……

> Typeless・開頭：我在研究一個 HDR 的影片，最近把 S-Log3 的素材全部拿來做剪輯。這當中我目前的感受是，HDR 的影片好像是一種取捨。

> 自己架的・開頭：我在研究一支 HDR 的影片，最近把 S-Log3 的素材全部拿來做剪輯。

原稿沒有標點、沒有斷句，連「S-Log3」都聽成「Xlog3」。兩種清稿都把它修好了，差別在**態度**：Typeless 會替你補寫，把中間一大段拆成 1、2、3 編號列點，字數多了兩成；自己架的這套規則是只去贅詞、不加字，字數反而少一點。哪種比較好，要看用途——要直接貼給別人讀，Typeless 那種比較像整理好的文件；要貼給 AI、希望它讀到的就是你講的話，不加字的比較安心。

## 自己架一個：轉文字這段不是瓶頸

我試著自己蓋一個類似的工具：按一下鍵盤的 Fn 開始講，再按一下，字就貼進游標。第一步先挑語音模型，三個能在 Mac 本機跑的開源模型，轉同一批共 68 秒的錄音：

| 本機語音模型 | 轉 68 秒音檔 | 實測問題 |
|---|---|---|
| Whisper large-v3-turbo | 3.6 秒 | 有標點，不會編句子；錯的多是同音字 |
| Breeze-ASR-25 | 6.8 秒 | 整篇沒有標點，同音字也會錯 |
| Qwen3-ASR-1.7B | 7.3 秒 | 內容最準，但會自己補一句沒講過的話 |

Qwen3-ASR 補出來的那句，原話只到「測試看看」，它多寫了「原因是這個工具本來就強制。」

三家都夠快，所以**卡住的不是轉文字**。後來我又從 turbo 換成完整版 Whisper large-v3，並關掉「參考前文」：turbo 會把「操作」聽成「插座」，帶前文時還會掉進重複同一句的迴圈；換過之後一段 108 秒的錄音轉完約 6–7 秒。

## 清稿：本機模型快，但還不能用

第二步是清稿。拿六篇自己的口播錄音（1.5 到 5.5 分鐘），比雲端和兩個本機模型（2026-08 影片當時的數字，Claude 現在已經快很多，見下面「還沒解的第一題」）：

| 清稿模型 | 一篇耗時（中位） | 實測問題 |
|---|---|---|
| Claude（雲端） | 30.6 秒 | 品質基準，但要連網 |
| Apple Foundation Model（本機） | 7.0 秒 | 自作主張改成編號列點 |
| Qwen3-8B（本機） | 11.8 秒 | 會吃掉開頭語氣詞，有時吞掉整句 |

本機兩家都比雲端快，但品質都還沒到可以每天用。所以我定的原則是**準確優先**：清稿走雲端，本機小模型只當斷網時的備胎。錯一個字，整句意思就差很多。

## 換 AI 開口：讓它好了自己講給你聽

語音輸入解決了「我怎麼講給 AI」。另一半是「AI 怎麼回我」。讓 AI 自己開口的好處是，你真的可以離開一段時間去打掃、去健身，它做完會自己唸給你聽。你只要跟它講好怎麼回：不要唸程式碼，把重點抽出來講。

我做了一個叫「導讀器」的小工具：AI 的回覆一推過來就開始唸。把這個做法寫成一份 Claude 的技能檔（skill），喊一句「用導讀器回我」，它之後每則回覆就固定這樣唸給你聽。

### 台灣腔的語音怎麼選

中文語音最大的坑是口音。我讓幾個候選唸同一句，先請 AI 判斷是台灣口音還是大陸口音，過關的才給耳朵決定：

| 語音 | 來源與成本 | 口音判別 |
|---|---|---|
| 曉臻／雲哲 | edge-tts zh-TW，免費、不用金鑰 | 台灣腔，現在在用 |
| Kore／Leda | Gemini TTS，要下「用台灣口音」的指示 | 台灣腔 |
| Charon | Gemini TTS，同上 | 大陸腔 |
| MiniMax speech-2.8-hd | 付費，中文質感最好 | 大陸腔，怎麼調都一樣 |

Gemini 的台灣腔也不是每句都穩，同一個聲音同一句指示，偶爾會抽到大陸腔，所以每句生完要再判一次口音。以每天讓 AI 唸個不停的用量，我選免費的 edge-tts：付費的好一點，但用量一大就會爆，自用免費層比較實在。

## 還沒解的第一題：清稿速度

用了幾個月，一直沒找到比 Typeless 更好的清稿方式。比的是**放開按鍵之後要等多久**才拿到字（2026-10 實測）：

| 放開按鍵後等多久（中位） | Typeless | 自己架的（Claude 清稿） |
|---|---|---|
| 短句（不到 60 字） | 1.4 秒 | 2.8 秒轉文字 0.6＋清稿 2.2 |
| 長段（200 字以上） | 4.1 秒 | 11.6 秒範圍 4.9–16.6 |
| 全部錄音 | 1.6–3.2 秒7–9 月各月中位 | 4.2 秒轉文字 0.6＋清稿 3.5 |

Typeless · 長段 · 4.1 秒

自己架的 · 長段 · 11.6 秒（2026-10）

自己架的 · 長段 · 30.6 秒（2026-08 影片當時）

橫條滿刻度＝30.6 秒。

### 怎麼量的

- **Typeless**：用它在本機留下的歷史紀錄時間戳推算，「寫回結果的時間 − 開始錄音的時間 − 錄音長度」＝放開按鍵後的處理時間。短句與長段的資料從 2026-08-01 到 09-23（之後我就沒再用 Typeless）：短句 332 筆中位 1.42 秒、長段 107 筆中位 4.13 秒，長段跟 8 月拍片時的 4.1 秒差不多。全部錄音的各月中位數（另含 7 月的紀錄）是 7 月 1.72、8 月 1.59、9 月 3.15 秒，9 月變慢約一倍。
- **自己架的**：用自己工具的執行紀錄，取最近 55 筆「放開按鍵到貼上」的秒數，短句 17 筆、長段 11 筆（清稿成品字數分組）。
- 兩邊都量放開按鍵之後的等待時間，也都用成品字數分組（不到 60 字＝短句、200 字以上＝長段）；但不是同一句話逐筆配對。

### 這兩個月改了什麼

影片當時，同一批六篇長錄音逐筆配對，是 Typeless 4.1 秒對我的 30.6 秒。之後做過的改動有：一開始錄音就先叫醒清稿模型、閒置時定時「心跳」，避免冷啟動（閒置一整天後第一句冷啟動曾要 19.2 秒）；短句同時送兩份搶答；給清稿模型的辭典只留正確寫法，從 2,002 字減到 590 字。9 月也試過換成 OpenAI 的 GPT-5.6 Luna 清稿（11 題抽測純清稿平均 2.10 秒），現在選單可以切換，上面這批 55 筆用的是 Claude。哪一項改動貢獻多少沒有拆開量。

Typeless 放開按鍵後很快就出字，看起來是邊錄邊轉，加上它可能有大量資料專門訓練清稿這件事。我把邊錄邊轉學過來了，所以轉文字只剩 0.6 秒；剩下的差距在清稿。拿我累積的六百多題錄音、以 Typeless 的成品當標準來比（2026-08 考卷），還輸它的有三處：清稿速度、用引號標出專有名詞、用括號收插入語。

## 還沒解的第二題：用自己的聲音、台灣腔回話

免費層裡，我沒找到比現在這個更好的台灣腔語音。下一步自然會想：拿開源模型在本機跑，用自己的聲音、或複製一個台灣腔的聲音。實測兩個最常被推薦的開源聲音複製模型：

| 開源模型 | 授權與本機速度 | 餵台灣人聲的結果 |
|---|---|---|
| CosyVoice 2 | Apache-2.0；Apple 晶片 GPU 約 1 倍即時 | 混血怪腔 |
| IndexTTS 2 | 權重限非商用；Apple 晶片 GPU 跑不起來，只能用 CPU（約 9.5 倍時長） | 混血怪腔 |

餵合成的台灣腔、餵我自己 9 秒的真人錄音，結果都一樣：出來是混血怪腔，我自己聽完的判斷是「都不能聽」。改餵大陸腔的樣本反而可以聽，但還是有聽不懂的腔調。結論是：**台灣腔的開源中文模型太少，目前做不出來**；硬要做到好，效率又差，不適合天天用，比較適合拿去做影視作品這種一次性的配音。

**這段能幫你做到什麼：**選出 Mac 上繁體中文語音輸入的方案（Typeless 或自己蓋），並用頁面的量測方法驗證速度。

**要先準備**

- Apple Silicon 的 Mac（WhisperBar 需要）。
- 自己的口述錄音，頁面方法用的是你自己的歷史紀錄或執行紀錄。
- 選自己蓋：[https://github.com/qwert2813434-ctrl/whisperbar](https://github.com/qwert2813434-ctrl/whisperbar)（本機語音輸入；repo 授權 MIT，README 寫沒有程式碼、是規格書）。

**步驟**

1. 先決定：要今天就用、在意放開就出字，選 Typeless。要錄音留在本機、只去贅詞不加字、自己養辭典，選自己蓋。
2. 選自己蓋：把 whisperbar repo 放進空專案。whisperbar README 寫：CLAUDE.md 是 agent 一進 repo 先讀的檔，BUILD.md 是施工順序主文件。
3. whisperbar README 寫：照 BUILD.md 第 0 到第 8 階段依序蓋；階段 1–4 先蓋完已能用（命令列版）。
4. README 寫：每階段先跑 ACCEPTANCE.md 對應那節，過了才做下一階段；ACCEPTANCE.md 教你用自己的錄音建考卷。
5. README 寫：遇到症狀先查 PITFALLS.md。
6. 量速度：記下放開按鍵到字貼上的秒數，按成品字數分組（不到 60 字為短句，200 字以上為長段），取中位數。
7. 如果量 Typeless：用它在本機的歷史紀錄，算「寫回時間 − 開始錄音時間 − 錄音長度」。
8. 要讓 AI 開口：aloud README 寫照 BUILD.md 第 0 到第 7 階段蓋。

**怎樣算完成**

- 按一下 Fn 開始講、再按一下，文字貼進游標。
- 依 whisperbar README，ACCEPTANCE.md 各階段通過。
- 你有自己的短句與長段中位秒數，可以跟頁面數字（作者當次：自己架短句 2.8 秒、長段 11.6 秒；Typeless 1.4／4.1 秒）對照。

**常見失敗與下一步**

- 轉文字錯同音字或掉進重複同一句：作者改用完整 Whisper large-v3 並關掉「參考前文」。
- 本機小模型清稿會改成列點或吞句：作者當次結論是清稿走雲端，本機只當斷網備胎；清稿速度仍慢，頁面列為還沒解的題目。
- 台灣腔語音：作者選免費的 edge-tts（曉臻／雲哲）。Gemini 的 Kore／Leda 偶爾抽到大陸腔，每句要再判一次口音。

**不要做的事**

- whisperbar README 寫：錄音、轉譯稿、辭典內容不放進 repo。
- whisperbar README 寫：請勿用任何商業 App 的資料庫、錄音或輸出當測試集或訓練材料，改用自己的錄音。
- 作者測的 CosyVoice 2、IndexTTS 2 未產出可接受的台灣腔（混血怪腔）；不推及其他模型。
- 不要把頁面數字當成一定如此；Typeless 持續更新，以目前版本為準。

- 開源聲音複製：CosyVoice 2、IndexTTS 2，M4 Max 本機實跑（2026.08.22）
- GPT 清稿試用：11 題考卷抽測（2026.09.13）

以上都是一個人、一台電腦、自己的口音與用詞實測，換人換機器數字會不同。Typeless 持續在更新，以它目前的版本為準。
