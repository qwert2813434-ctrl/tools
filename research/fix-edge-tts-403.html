朗讀突然沒聲音：微軟換了配音主機

發生 2026.10.12影響 所有用 edge-tts 的工具最後驗證 2026.10.12
一句話：微軟關掉了舊的 Edge 配音主機，所以 Aloud 和唸書機會突然不唸、不出音檔。程式本身沒壞。換到微軟的新主機就好：裝現成版的人貼一行指令更新，自己蓋的版本加三行程式。

症狀

  • Aloud：文字推得進去、畫面也有，就是不唸；或一直停在「合成中」。
  • 唸書機：配音或建置跟讀器時中斷，沒有產生音檔。
  • 錯誤訊息是 403, message='Invalid response status'（網址含 speech.platform.bing.com），或只看到 RuntimeError: Session is closed。

不是時鐘問題，也不是 edge-tts 版本太舊：7.2.8 是目前最新版，一樣 403。

你是哪一種，照哪一段做

A. 裝了 Aloud 現成版（貼一行指令裝的）

打開「終端機」，貼上當初安裝的同一行指令。會更新到 2.3 版，你的破音字表會保留。更新完重開導讀窗。

curl -fsSL https://raw.githubusercontent.com/qwert2813434-ctrl/aloud/main/install.sh | bash

B. 用唸書機（從 GitHub 下載的）

到唸書機資料夾，拉最新版就好。已修好的兩個檔是 跟讀器建置.py 和 對照建置.py。

git pull

沒有用 git、是下載 zip 的：照下面 C 段，在這兩個檔的 import edge_tts 後面加三行。

C. 照 Aloud 規格書自己蓋的，或任何用 edge-tts 的程式

在 import edge_tts 的下一行加這段，把連線改到新主機。不用改套件本體。

import edge_tts.communicate edge_tts.communicate.WSS_URL = ("wss://api.msedgeservices.com/tts/cognitiveservices/websocket/v1" "?Ocp-Apim-Subscription-Key=" + edge_tts.constants.TRUSTED_CLIENT_TOKEN)

如果 import edge_tts 寫在函式裡面，這三行也放在函式裡面，縮排要對齊。改完要重開伺服器，舊的程序還在跑，就不會用到新程式。

給 AI Agent：照這個步驟修

把這頁網址丟給你的 Claude、Codex 或其他 agent，跟它說「照這頁修」。

  1. 先判斷是哪一種安裝（上面 A／B／C）。A 只要執行那行安裝指令，然後重開 App，就跳到第 5 步。
  2. 在專案裡搜尋 import edge_tts，列出所有命中的 .py 檔（不含 site-packages）。
  3. 每個命中處的下一行，加上 C 段那三行，縮排跟 import edge_tts 同一層。已經有 msedgeservices 的檔案跳過。
  4. 每個改過的檔跑 python3 -m py_compile 檔名，確認沒有語法錯誤。
  5. 驗證：用同一個 Python 合成一句中文，要拿到大於 0 位元組的音檔。
    python3 -c " import asyncio, edge_tts, edge_tts.communicate edge_tts.communicate.WSS_URL = ('wss://api.msedgeservices.com/tts/cognitiveservices/websocket/v1?Ocp-Apim-Subscription-Key=' + edge_tts.constants.TRUSTED_CLIENT_TOKEN) async def t(): n = 0 async for c in edge_tts.Communicate('測試', 'zh-TW-HsiaoChenNeural').stream(): if c['type'] == 'audio': n += len(c['data']) print('OK', n) asyncio.run(t())"
  6. 重開有在跑的伺服器（Aloud 的導讀窗要整個 App 結束再開），推一句文字，確認真的有聲音。
  7. 不要刪除或降級 edge-tts 套件；不要改 site-packages 裡的檔案。

之後

edge-tts 官方已有人送出同樣的修正（GitHub PR #491）。官方出新版之後，這三行可以留著，不會衝突。

Edge 配音本來就是非官方端點，微軟隨時可能再改。Aloud 規格書的「地雷第 10 條」有完整紀錄。
