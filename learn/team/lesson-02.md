# 普通篇：把 AI 變成你的團隊｜第 2 課　角色越多，AI 不會越聰明

網址：https://tools.arminkao.com/learn/team/lesson-02.html

> 這一課做完，你會：分得出什麼時候該「派一個角色去做」、什麼時候自己跟它聊就好；做出你的第一個角色。

## 這一課帶走

- 判斷句：「我要的是結論，還是要邊聊邊改？」
- 技能還是角色對照表
- 一句交代：「建一個角色，什麼時候派它、先讀（檔案）、交（格式），鎖成只讀。」
- 報告回來，至少驗一條。

## 給 AI Agent：照這段做

把這頁網址丟給你的 AI，說「照這頁幫我做」。（只對你信任的網站這樣做；陌生網頁別叫 AI 照做。）

以下以 Claude Code 為例。用 Codex 等其他產品時，先確認它支援的做法，改用它官方的設定方式（例如 Codex 讀 `AGENTS.md`），不要直接建立同名檔案。

你是使用者的 AI agent，在使用者的工作資料夾裡。

- **步驟**：
  1. 問使用者最近有哪些「只要一個結論」的事（審查、從很多檔案找答案、比對）。列出來，標出哪件最適合當第一個角色，附理由。
  2. 使用者挑一件。問清楚三件事：要先讀哪些檔案、交回來的格式、能不能改檔（預設只讀）。
  3. 寫成角色檔，放在這個資料夾的 `.claude/agents/<名字>.md`：開頭設定寫名字、description（寫清楚「什麼時候派」，主 AI 靠這句決定自己派不派）、tools（審查角色只給讀取類工具）；內文寫要讀哪些檔、照什麼格式交。
  4. 派這個角色做一次，把報告給使用者，並請使用者挑一條自己打開檔案驗證。
- **完成**：角色做完一次並交回報告；使用者驗過其中一條。
- **不要**：把大量知識直接寫進角色檔（知識放檔案，角色檔只寫去哪裡讀）；給審查角色改檔權限；在角色檔裡寫帳號密碼。
